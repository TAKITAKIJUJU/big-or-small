# NPCの読み合い

2026-11-14更新。上級を中心に、公開された行動と履歴から相手を推定して選ぶ。外部LLMやAPIは使わず、ブラウザ内で動く。キャラクターの超人的な思考や読心を再現したと主張しない。

## 抽選前の札選び

1〜13の残り札を等確率で引く方式を改める。各候補を「今回、BIG/SMALLが出たあとに張れる価値」と「後半に残した場合の価値」で比較する。

- 後半ほど参加料と追加上限が大きい。極端な札は、片方の抽選で強く張り、逆なら降りる選択を持つ。その価値を後半へ残す。
- 残チップが少なく次の参加料が重いときは、将来の価値を割り引き、今使う札を優先する。
- 常に中間札から出すような固定順にもせず、評価から重みを付けて選ぶ。上級の最低限の混合率は8%、中級22%、初級55%。混合は選択が固定されないためのもので、中心は候補の評価。
- 選札時にBIG/SMALLや相手の選択札は入力にない。抽選は選札確定後に別の乱数で行う。

## 相手の札候補

`opponent-model.ts` は13枚の残り集合をビット集合として扱う。最大8192集合・約5万の状態遷移に収まる。

公開された札を使用済みから除く。非公開で捨てた札には複数の可能性を残し、公開された行動の起こりやすさで重みを更新する。後の公開札が以前の仮説と矛盾すればその仮説を除く。実際の相手の手札やFOLD札は参照しない。

大きいベットの尤度は、強い札のバリューと弱い札のブラフの両峰を持つ。全額だから必ず最強、または必ず最弱とは扱わない。隠れた使用済み札は、あり得る札として候補に残る。

この分布はモデルを仮定した推定であり、人間の真の意図や正確な勝率を知る機構ではない。公開履歴が少ないときは事前分布の影響が強い。

## 行動と金額から読むこと

- 小さい賭け、大きい賭けに対して降りた比率。
- 賭ける頻度、受ける頻度、公開された大きい賭けが弱い札だった比率。
- 強い札でチェックし、その後に受けた／賭けた履歴。
- NPC自身が公開したブラフや強い札。相手からどう見えていそうかを推定する。

過去の真偽を学習するのはショーダウンで公開された札だけ。試合後の開示設定で見えるようになったFOLD札も、戦略の正解として遡って利用しない。推定には事前の件数を加え、一度見ただけで「いつもブラフ」と断定しない。

## 賭け方

上級は `betting-search.ts` のCFR+型の反復探索（128反復）を使う。今のラウンドでチェック、ベット、コール、フォールド、最大2回のレイズが終わるところまで木を作る。金額は最小・半ポット付近・ポット付近・最大へ抽象化する。どの枝もエンジンの `getLegalActions` から作り、端数や短いスタックの規則も共通にする。

各節点に「自分の札×行動」の戦略と後悔値を持つ。相手札の仮説ごとに違う自分の応答を選ぶ透視探索は行わない。自分の同じ札・同じ公開履歴には、一つの混合戦略を割り当てる。相手が想定するNPCの札も、NPCの本当の残り手札ではなく、公開情報から作る範囲を使う。

相手側は、観測した行動モデルを15〜70%弱の割合で混ぜ、残りで対抗戦略を反復計算する制約付きのゲームとして解く。観測件数が増えるとモデルの割合が増える。相手の実際のフォールド頻度とポットオッズで、札ごとの降りる率を校正する。最初から「相手は必ずこの通り動く」として最適化しない。

その結果、単に賭けてコールされる場合だけでなく、チェック後に賭けられたときの返し、レイズされたときのコール／フォールド／再レイズまで比較する。強い札と弱いブラフに同じ金額が混ざり、賭け方だけでは実札を一意に読めない戦略を作る。

- よく降りる相手には、弱めの札でもブラフが利益になることがある。
- よく受ける相手には、弱いブラフを減らし、強い札で受けてもらう価値が上がる。
- よく賭ける相手には、強い札でチェックして次のベットを待つ価値を評価する。
- 大きいブラフを何度も公開した相手には、中程度の札でもコールが候補になる。
- NPCがブラフを見せたあとには、受けられやすいと見込み、強い札で大きく賭ける候補が変わる。強い札を見せた印象をブラフに使う場合もある。
- 終盤はチップ差を考慮。最終回は期待チップだけでなく、試合に勝つ／引き分ける確率を優先する。相手の札候補から絶対に負けないことが分かる場合はFOLDを候補から除く。

上級の行動は、後半の反復で得た戦略を到達確率で重み付けして平均し、そこから選ぶ。初級・中級は以前の軽い候補評価と重み付けを使う。新規設定の初期値は上級。保存されている難易度は引き継ぐ。

13回全体の完全解ではない。札の温存は将来の参加料を使った近似、相手の範囲は仮定付きの推定、賭け金は一部の額へ抽象化し、反復回数も有限。再探索時の範囲にも近似があり、ナッシュ均衡や絶対的な最強を保証しない。

## 強さの比較

旧上級の公開コミット `138d63f` の選札・行動・推定モデルを `tests/baselines/` に固定。製品バンドルには含めない。両者の札選びは同じ旧方式なので、主にベッティング部分の改善を比較できる。

各乱数seedで先手・後手を交換した2試合を行う。対戦者ごとの行動乱数は座席交換後も同じ系列、各回のBIG/SMALLも同じ系列を使う。結果は試合勝利1、引分0.5、敗北0。95%区間は2試合を一組とした平均の標準誤差から計算する。

2026-11-14、調整に使用しないseed 1001〜1200・通常の参加料上昇ルールで、旧上級へ **241勝・2分・157敗（400戦）**。引分を半勝にした得点率60.5%、組単位の95%区間55.5〜65.5%。相手の癖やカードを学習済みにして始める操作はしない。

別の固定戦略にも各320戦で勝ち越した（全額で攻撃212勝、すべて受ける216勝1分、強い札だけ197勝）。すべての人間や未知の戦略への強さを証明する結果ではない。全ラウンド全額ONでは旧上級と240戦で134勝106敗、55.8%、区間49.2〜62.5%で、改善の確証は通常ルールより弱い。

再実行例：

```sh
ARENA_SEEDS=200 ARENA_START_SEED=1001 ARENA_RIVALS='旧上級 v2' npm run test:arena
ARENA_SEEDS=120 ARENA_START_SEED=2001 ARENA_ALL_IN=1 ARENA_RIVALS='旧上級 v2' npm run test:arena
```

`ARENA_REPORT=/絶対パス/report.json` で測定JSONを保存可能。通常検査とは分離し、160seed以上で旧上級の比較を行う場合は95%区間の下端が50%を超えることも検査する。[通常比較](benchmarks/npc-v3-default.json)、[固定戦略](benchmarks/npc-v3-styles.json)、[全額ON](benchmarks/npc-v3-all-in.json)。

## 試合後の説明と保存

判断したその時点で「温存」「ブラフ」「誘い」「ブラフを疑ってコール」などの理由コードを保存する。終了後の札を見て説明を創作しない。表示文は静的な日本語で、LLMの台詞生成は使わない。

対戦中は判断ログをUIへ渡さない。試合終了かつ全カード開示ONの場合だけ履歴へ表示する。OFFでは表示せず、設定をONにすれば開ける。ホームから前の対戦の振り返りを開け、再読込後も記録は残る。

保存するのは同じ試合の判断記録。試合を越えて人間の癖を永久学習する機能は今回入れていない。新しい試合では推定を初期化する。旧セーブは理由記録がなくても再開できる。

## 公平性と性能

入力はPlayerViewのみ。GameState、将来の乱数、人間の伏せ札を引数にしない。人間の秘密札や非公開FOLD札だけを変えた反実仮想でも、推定分布と同じ乱数での行動が一致することをテストする。

同じ公開ビューの推定だけをWeakMapでメモ化し、保持し続けない。自己対戦や合法ランダム対局でも同じ合法手検証を通す。

上級の探索はWeb Workerで行い、メイン画面の描画とタッチを止めない。ワーカーへもPlayerViewしか送らない。ホーム・ダイアログ・横向き・再戦で処理を中止し、古い状態に対する結果は参照同一性も確認して破棄する。Workerが拒否される環境では同じ方策をメインスレッドで計算して継続する。

最終の通常比較のNode実測は中央値約6.2ms・p95約63.2ms（ブラウザ検査も同時実行）、全額ON比較ではp95約77ms。処理時間は同時負荷で変動し、ブラウザやAndroidの速度へ換算しない。Android実機未検証。
